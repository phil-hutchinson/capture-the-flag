# Peer Review — 00000026 Input feature engineering (flag-relative distance and army strength)

## Summary

The branch widens the play engine's encoding from 18 to 34 planes — four
flag-relative signed-offset planes and twelve broadcast army-strength planes —
mints `ENG_NN_2` to document the new tensor contract, adds engine-spec and
architecture stamps to every checkpoint (spec mismatch rejected, architecture
difference reconstructed), and turns `CtfCrn`'s trunk width and depth into
constructor parameters that flow through `TrainingConfig`, the training runner's
flags, and `run-config.json`. All ten plan steps are present, the encoder matches
the spec's plane indices, and the story's acceptance criteria are substantially
met.

Static checks: **`pyright` — 0 errors, 0 warnings, 0 informations.**
**`ruff check .` — all checks passed.** The default test suite passes (244
passed, 7 deselected).

The findings below were mostly documentation accuracy and code-hygiene items, and
all fifteen have since been resolved — ten fixed, five closed without change. The
test-suite reclassification raised in #2 and #3 — several previously-default
tests, including the end-to-end game, moved behind the `slow` marker — was
reviewed and closed as intended; those tests remain `slow`-marked and the
marker's broadened definition stands.
