# Peer Review — Rulesets, editions, and rule flags (Story 00000032)

## Summary

The branch replaces the single mutable `<version>:<name>` ruleset identifier with
the ruleset / edition / flag model across all four surfaces the plan names: the
project vocabulary, the `doc/ruleset/` documents (two new appendices, a new
`proposed-variants.md`, and a full policy rewrite), the record writer's edition
table and resolved-configuration helpers, and the checkpoint / run-config stamps
with their cross-check on resume. All eight plan steps are present and in order,
the documentation is unusually thorough, and the test coverage matches what each
step's verification section asked for.

`pyright` reports **0 errors, 0 warnings, 0 informations**; `ruff check .`
reports **All checks passed!**; `pytest` (default, non-slow) is **365 passed, 16
deselected**. The findings below are all about the gap between what the story and
the new docstrings promise about *adoption* of a stamped configuration and what
the code actually does with one, plus smaller robustness and consistency nits.

## Resolution pass

All nine items are resolved; none was declined. The two major items were both
taken the strict way — adoption is implemented rather than the docs narrowed
(#1), and an edition this build does not implement is refused rather than
accepted on table membership (#2) — because both were about the stamp meaning
what it claims, which is the whole point of the story.

Worth noting that #1 and #2 are each unobservable under the currently published
data (one edition, no flags), so their tests supply a hypothetical flag or a
hypothetical later edition, as the Step 3 tests already do. The adoption test was
confirmed to fail against the pre-fix code rather than merely passing after it.

After the pass: `ruff check .` **All checks passed!**, `pyright` **0 errors, 0
warnings, 0 informations**, `pytest` **375 passed, 16 deselected** (up from 365 —
ten new tests), and `pytest -m slow` **16 passed**, which exercises the real
resume path the adoption change runs through.
