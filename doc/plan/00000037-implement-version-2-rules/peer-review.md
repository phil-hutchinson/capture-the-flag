# Peer Review — Story 37: Implement Version 2 Rules

## Summary

The branch turns board geometry and army composition from module constants into
values carried by a `BoardLayout` / `ArmyComposition` pair (`GameSetup`), adds
diagonal attack to move generation, widens the policy action space to twelve
movements, threads a run-selected `RulesetConfiguration` from the CLI through
every runner and every stamped artifact, and publishes `2-1:SKIRMISH` behind a
new `TOWER_PLACEMENT` flag. All thirteen plan steps are present and in the order
the plan set out, including the README review (step 13) and the training-run
retirement (step 12, verified against the gitignored directory and the story-29
findings note).

Tooling is clean: `pyright` reports **0 errors, 0 warnings, 0 informations**, and
`ruff check .` reports **All checks passed!**. The full suite passes (454 passed,
16 deselected). No Critical findings. The two Major findings are a stale engine
spec document that names a now-historical edition as its compatible ruleset, and
a `GameSetup` invariant gap that lets a setup stamp itself with a configuration
it does not actually implement.

**All fifteen findings have since been fixed** (see their Resolution entries).
After the fixes, `pyright` reports 0 errors and `ruff check .` passes; the suite
is 460 passed, 16 deselected, and the 16 slow-marked tests pass as well. Six
tests were added: three pinning the new `GameSetup` configuration invariant, one
for the off-board lake row, and two for the network/board agreement check.
