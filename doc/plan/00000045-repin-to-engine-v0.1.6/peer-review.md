# Peer Review — Story 45: Repin to `game-engine-core` v0.1.6

## Summary

The branch moves the pin from `v0.1.4` to `v0.1.6` and converts the three seams
v0.1.5 pluralized — the evaluator (`encode_positions` / `decode_policies` /
`evaluate_positions`), the capture-time policy transform, and `TimedMCTSEngine`'s
self-play search override — plus the `PolicyLossFn` device contract, the
`search-with-policy` → `search-for-training` rename, the fleet-width
documentation of `--games`, a fresh batch-of-one timing baseline, and the
`CONTRIBUTING.md` correction. The conversions are faithful to the new upstream
signatures, the new tests genuinely pin index alignment (mixed-mover batches,
disjoint legal-ply key sets) rather than passing width-1 calls through plural
methods, and the plan's Step 8 does include the required `README.md` check.

Verification run for this review: `pyright` reports **0 errors, 0 warnings, 0
informations**; `ruff check .` reports **All checks passed!**; `pytest` is green
(485 passed) and `pytest -m slow` is green (16 passed). The installed
distribution's `direct_url.json` names `v0.1.6` at commit
`74c6ea0260bcbd1a0e1569de3f3030149104dd3d`, matching the pin. Findings below are
therefore about contract coverage, plan/story alignment, and style — not about a
red tree.
